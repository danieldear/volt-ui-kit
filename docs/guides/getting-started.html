Guide

Getting started

Install the kit, create a project and open your first native window.

Volt UI Kit builds desktop interfaces in plain Rust. You write a function from your application state to a tree of elements; the kit lays it out, draws it on the GPU (or the CPU as a fallback), routes input and accessibility, and calls your Rust closures when something happens.

Add the dependency

Version 0.5.0 is prepared in the repository but is not yet on crates.io. Use a Git or path dependency until it is published:

tomlSource
[dependencies]
volt-ui-kit = { git = "https://github.com/danieldear/volt-ui-kit", features = ["native-gpu"] }

Rust 1.89 or newer is required. Pin a reviewed Git revision using rev and commit your app's Cargo.lock for reproducibility; a moving default branch is not a versioned release.

Features

Nothing is enabled by default; pick what your application needs.

FeatureAdds
nativeA window host: winit, cosmic-text, software drawing (tiny-skia), images, clipboard, IME and AccessKit accessibility. Includes rust-ui.
native-gpuGPU drawing with Vello on wgpu (Metal, DX12 or Vulkan), with automatic software fallback. Includes native.
native-desktopmacOS application menus, a tray menu, and native open/save panels.
native-notificationsmacOS local notifications.
rust-uiThe Rust builders (ui module) without a window, for custom hosts.
declarativeThe validated document tree, runtime and optional JSON frontend.
dev-toolsThe cargo volt command: project templates, a rebuild-and-restart dev loop, and macOS app bundles.

Most applications want native-gpu. Add native-desktop for menus and file panels.

Your first window

rustSource
use volt_ui_kit::{native::Application, ui::prelude::*};

#[derive(Default)]
struct App {
    count: u32,
}

fn view(app: &App) -> Element<App> {
    vstack![
        text(format!("Clicked {} times", app.count))
            .font_size(24.)
            .font_weight(600),
        button("Click me")
            .key("add")
            .variant(ButtonVariant::Primary)
            .on_click(|app: &mut App| app.count += 1),
    ]
    .padding(24., Edge::All)
    .gap(12., Axis::Vertical)
    .into()
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    Application::new("Counter", App::default(), view)
        .size(480, 320)
        .run()
}
  • App is your state. The kit never owns or copies it.
  • view describes the screen for the current state. It runs once at start and again after every callback, so keep it free of I/O and side effects.
  • Callbacks receive &mut App. Change state there; the next view shows it.
  • .key("add") gives the button a stable identity, so focus and animation survive recomposition. Key every interactive element in a dynamic list.

Application defaults to the system light/dark theme, GPU drawing when compiled in, and an ordinary native title bar. See Windows and rendering to change that.

Start from a template

cargo volt creates a project and runs it with automatic rebuilds:

shSource
cargo install --locked --path . --features dev-tools --bin cargo-volt

cargo volt new my-app --kit-path /path/to/volt-ui-kit --template navigation
cargo volt dev my-app

Templates: minimal, navigation, mail, settings and agent. Add --desktop for macOS menus and a tray item. new never overwrites an existing directory. All but minimal start from navigation_split_view, the Catalog's own sidebar-and-detail shell, with a sidebar you resize by dragging its divider. Every template also uses the Catalog's colours: its theme() function picks Palette::zinc_light() or Palette::zinc_dark() to match the system appearance (see Built-in palettes).

cargo volt dev watches your sources, rebuilds on save and restarts the app after a successful build; a failed build leaves the running app alone. Apps that call Application::dev_state keep their state and window position across restarts.

Explore the components

The Catalog example shows components with live previews, source code, API tables, themes and a working dashboard. From a repository checkout:

shSource
./scripts/run_catalog.sh

This is the recommended full-demo path: it enables GPU, desktop integrations and notifications, builds and signs an identified macOS .app, registers it before launch, and opens it. Notification permission is requested only when you click its button. The launcher requires Cargo and Python 3; macOS also needs the command-line tools. Use --check to build/verify without opening. The script is a repository tool, not part of the crates.io package.

For targeted component development or snapshot flags, launch directly:

shSource
cargo run --release --locked --features native-gpu,native-desktop --example catalog -- --page dashboard --theme dark --accent violet

That direct command does not package the app or enable the notification adapter; use the full launcher for the notification demo. --features native is the software-only alternative. See the launch-mode table.

Useful direct flags: --page dashboard, --theme light|dark, --accent violet. Page names are the sidebar titles in lowercase with hyphens, for example --page theme-editor or --page form-inputs. These flags are not accepted by the launcher script, which intentionally only accepts --check and --help.

Platform support

PlatformStatus
macOS 11+Primary platform; tested on Apple silicon with Metal.
WindowsCross-compilation checked; headless CI configured (DX12). Native runtime not yet validated.
LinuxCross-compilation checked; headless CI configured (Vulkan, X11/Wayland). Native runtime not yet validated.
iOSExperimental reusable host/template: Rust screens without per-app Swift glue. Simulator workflows tested; physical-device GPU acceptance pending.
AndroidCommon Rust application/event layer only; no Activity, IME host, APK or project template yet.
WebAssemblyExperimental browser host: live Rust buttons, tabs, forms and scrolling with WebGPU/software rendering; not full web parity.
