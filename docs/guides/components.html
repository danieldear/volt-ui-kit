Component recipes

A practical overview of the Rust component builders.

Every component is a Rust builder that returns an element. Components are controlled: they show values from your state and report changes through typed callbacks, so the state stays in one place. Each one has a live page in the Catalog (--page <name>), with its source and API table.

Common rules:

  • Interactive components need a .key(..) when they appear in dynamic content, and every interactive callback must be connected or build() fails.
  • Selections take typed values (Clone + PartialEq): enums, integers or your own types, never label strings.
  • Choosing the already-selected option does nothing and does not recompose.
  • Popups, menus and dialogs are drawn inside the window and keep focus and input inside their scope while open.

Buttons and actions

rustSource
use volt_ui_kit::ui::prelude::*;
let actions: Element<()> = hstack![
    button("Save").key("save").variant(ButtonVariant::Primary).on_click(|_: &mut ()| {}),
    button("Preview").key("preview").variant(ButtonVariant::Soft).on_click(|_: &mut ()| {}),
    button("Cancel").key("cancel").variant(ButtonVariant::Ghost).on_click(|_: &mut ()| {}),
    button("Delete").key("delete").variant(ButtonVariant::Danger).size(ControlSize::Small)
        .on_click(|_: &mut ()| {}),
    button("Sort by").key("sort").disclosure(false).label_align(Align::Start)
        .width(140.).on_click(|_: &mut ()| {}),
]
.gap(8., Axis::Horizontal)
.into();
actions.build()?;
  • Variants: Neutral, Primary, Soft, Outline, Ghost, Danger. Sizes: Small (28 px), Medium (36 px), Large (44 px). Both are theme presets; later .background(..), .color(..) or .hover_style(..) calls win.
  • .disclosure(open) adds a trailing chevron, as used by select and menu triggers.
  • button_bar![..] groups actions; .joined(true) makes a segmented strip. toolbar![..] lays out a horizontal application toolbar.

Rich text

rich_text lays out one paragraph made of differently styled runs. It wraps, aligns and truncates as a single text and takes every text modifier:

rustSource
use volt_ui_kit::ui::prelude::*;
let note: Element<()> = rich_text([
    span("Run "),
    span("cargo test").code(),
    span(" before you "),
    span("push").bold(),
    span(", or CI will fail.").color(ColorToken::Error),
])
.font_size(15.)
.line_height(1.6)
.max_lines(3)
.into();
note.build()?;
  • A span can set .bold() or .weight(w), .italic(), .family(name), .size(scale), .color(c), .background(c) (a rounded chip), .underline() and .strikethrough(). .code() is monospace at 0.88× on a subtle background. Unset properties inherit the text's style.
  • .link(target) makes a run a link: primary colour, pointer cursor and an underline on hover. .on_link(|app, target| ..) on the text receives the target of the link that was clicked. Keyboard focus for links is not available yet.
  • Colours apply when drawing, so a colour change never reshapes the text.
  • Runs keep their styles where lines break; max_lines ends with an ellipsis.
  • Up to 1,024 spans per text, within the usual 8 KiB of text.

Navigation and tabs

rustSource
use volt_ui_kit::ui::prelude::*;

#[derive(Clone, Copy, Default, PartialEq)]
enum Page { #[default] Overview, Activity }
#[derive(Default)]
struct App { page: Page, count: usize }

fn view(app: &App) -> Element<App> {
    vstack![
        toolbar![
            text("My workspace").font_weight(600),
            spacer(),
            button_bar![
                button("Add").key("add").on_click(|app: &mut App| app.count += 1),
                button("Clear").key("clear").enabled(app.count > 0)
                    .on_click(|app: &mut App| app.count = 0),
            ].joined(true),
        ],
        segmented_control([(Page::Overview, "Overview"), (Page::Activity, "Activity")])
            .key("page-picker")
            .selected(app.page)
            .on_select(|app: &mut App, page| app.page = page),
        tabs![
            tab(Page::Overview, "Overview", text(format!("Count: {}", app.count)))
                .key("overview-tab"),
            tab(Page::Activity, "Activity", text("Only the selected page is mounted"))
                .key("activity-tab"),
        ]
        .key("pages")
        .selected(app.page)
        .placement(TabPlacement::Top)
        .on_select(|app: &mut App, page| app.page = page),
    ]
    .gap(16., Axis::Vertical)
    .into()
}
view(&App::default()).build()?;
  • segmented_control, tab_bar![tab_item(..), ..] and tabs![tab(..), ..] select typed values. tabs mounts only the selected page; keep page data in your state. Item .enabled(false) disables one option.
  • Tabs draw as text over a hairline, with the selected tab underlined in the primary colour. .variant(TabVariant::Contained) draws a raised chip in a quiet track instead. Segmented controls keep their joined look.
  • navigation([navigation_item(value, "Label"), ..]) is an app-level destination list with NavigationPlacement::Sidebar, Rail or Bottom, drawn like the Catalog's sidebar. Item .section("Title") groups consecutive items under a sidebar heading; .badge("New") adds a trailing badge. .selected(None) highlights nothing.
  • navigation_split_view(|place| sidebar, detail) is the Catalog's app shell, like SwiftUI's NavigationSplitView: the sidebar beside a detail column with a draggable .toolbar(..), room for the macOS window controls, and an optional resizable divider (.on_sidebar_resize). The sidebar closure runs once for its column and once for the drawer that replaces it below Lg; build its keys with place.key("nav") so the two stay distinct. Wire .drawer_open(..) and .on_drawer_change(..) to app state for the menu button and drawer; .material(true) floats the detail over a translucent window. It is optional: compose your own shell from stacks when you need to.
  • With an option focused, arrow keys and Home/End move the selection.

Typed navigation and web links

navigation still controls destination selection; routing is optional. For Back/Forward navigation, keep NavigationHistory<Route> in your app state. navigation_link passes a typed destination to your callback, and navigation_stack composes only the current route.

rustSource
use volt_ui_kit::ui::prelude::*;

#[derive(Clone, PartialEq)]
enum Route { Home, Activity }
struct App { history: NavigationHistory<Route> }

fn view(app: &App) -> Element<App> {
    vstack![
        navigation_link("Activity", Route::Activity).key("activity")
            .on_navigate(|app: &mut App, route| { app.history.push(route); }),
        button("Back").key("back").enabled(app.history.can_go_back())
            .on_click(|app: &mut App| { app.history.back(); }),
        navigation_stack(&app.history, |route| match route {
            Route::Home => text("Home").key("home-page").into(),
            Route::Activity => text("Activity").key("activity-page").into(),
        }).key("current-page"),
    ].into()
}
let mut history = NavigationHistory::new(Route::Home);
history.push(Route::Activity);
let checkpoint = history.snapshot();
assert!(history.back());
history.restore(checkpoint).unwrap();
assert!(matches!(history.current(), Route::Activity));

History defaults to 128 entries; with_capacity(root, 1..=1024) customizes the bound. Pushing the current route does nothing, including preserving Forward. Pushing after Back discards the forward branch; overflow removes the oldest entry. replace(route) changes only the current entry; reset(root) clears history. NavigationSnapshot supports Serde; restore validates its length and index before changing anything. Bound serialized input before deserializing. Persistent page models, scroll/focus restoration, route decoding and OS deep-link registration are application responsibilities, not automatic behavior. Use route-specific keys for independent page controls.

rustSource
use volt_ui_kit::ui::prelude::*;
#[derive(Default)]
struct App { destination: Option<ExternalUrl> }
let ui: Element<App> = link("Read the guide ↗", "https://example.com/guide")
    .key("guide")
    .on_open(|app: &mut App, url| app.destination = Some(url))
    .into();
ui.build().unwrap(); // Does not open a browser or perform I/O.

Standalone links require a nonempty label, stable key and callback. They support shared style modifiers, theme colors, hover/press/focus feedback, Tab/Shift-Tab and Enter activation, plus .enabled(false). Native AccessKit exposes a Link role and the external URL. Custom hosts can read Runtime::accessibility_links() alongside accessibility_nodes(); the legacy AccessNode/AccessRole shapes are unchanged. A None URL denotes an internal navigation link. Removed, disabled or out-of-modal-scope links cannot activate through the runtime.

ExternalUrl::parse accepts absolute ASCII HTTP(S) URLs up to 4096 bytes. It rejects credentials, malformed ports/escapes, whitespace/control characters and executable/local-file/custom schemes. Encode Unicode domains/paths first. Validation does not imply that a website is trustworthy. Inline span(..).link(..) remains a separate rich-text callback API; standalone-link keyboard behavior does not make individual inline spans focusable. See browser dispatch for explicit native opening. Try both workflows on the Catalog's Navigation page.

Customizing component spacing

Constructor sizes are defaults, not fixed design requirements. Keep the defaults for a consistent starting point, or override the part you actually need. Values are logical pixels; explicit 0. works, edge/axis arrays are supported, and the last setter affecting an edge or axis wins. Padding is inside a component; gap separates its immediate children, not every nested label or icon.

rustSource
use volt_ui_kit::ui::prelude::*;
let picker: Element<()> = tab_bar![tab_item(0, "Space"), tab_item(1, "Duplicates")]
    .key("picker").selected(0).on_select(|_: &mut (), _| {})
    .gap(responsive(2.).at(Breakpoint::Md, 8.), Axis::Horizontal)
    .padding(4., [Edge::Top, Edge::Bottom])
    .into();
picker.build()?;
let pages: Element<()> = tabs![
    tab(0, "Overview", text("Overview")),
    tab(1, "Details", text("Details")),
].key("pages").selected(0).on_select(|_: &mut (), _| {})
 .tab_gap(6.).tab_padding(4., Edge::Horizontal)
 .gap(16., Axis::Vertical).into();
pages.build()?;
let actions: Element<()> = menu("Actions", [menu_item(0, "Open"), menu_item(1, "Copy path")])
    .key("actions").open(false)
    .on_open_change(|_: &mut (), _| {}).on_action(|_: &mut (), _| {})
    .popup_padding(8.).item_gap(4.).item_height(38.)
    .popup_max_height(320.).popup_background(ColorToken::Base100).into();
actions.build()?;

Stack-style spacing and tab strip overrides accept responsive values. Table/tree panel spacing and density, popup geometry, OTP and combobox result gaps are fixed logical values: use a responsive containing stack for their outer placement. Table .gap(..) also separates its divider children; use .row_height(..) for ordinary table density. A drawer/command-palette override targets the card, not its modal backdrop. Intrinsic glyph dimensions and hit-target geometry are not silently changed by a content gap.

Non-finite, negative and out-of-range values fail build(). Popup item height must be 24–512, popup maximum height 24–8192, table/header height 24–512, tree row height 28–512; the viewport can shrink a popup further, with overflow scrolling. Zero spacing does not change callbacks, selection, keyboard behavior or defaults of controls which do not opt in.

Fields, value controls and dialogs

rustSource
use volt_ui_kit::ui::prelude::*;
#[derive(Clone, Copy, Default, PartialEq)]
enum Order { #[default] Recent, Name }
#[derive(Default)]
struct App { draft: String, notes: String, level: f32, order: Order, picker: bool, review: bool }
fn view(app: &App) -> Element<App> {
    zstack![
        vstack![
            text_field(&app.draft).key("draft").placeholder("Draft title")
                .on_change(|app: &mut App, text| app.draft = text)
                .on_submit(|app: &mut App| app.review = true),
            text_area(&app.notes).key("notes").height(120.).soft_wrap(true)
                .on_change(|app: &mut App, text| app.notes = text),
            slider(app.level).key("level").range(0.0..=100.0).step(5.)
                .on_change(|app: &mut App, value| app.level = value),
            select([
                select_item(Order::Recent, "Recent").key("recent"),
                select_item(Order::Name, "Name").key("name"),
            ]).key("sort").selected(app.order).open(app.picker)
                .on_open_change(|app: &mut App, open| app.picker = open)
                .on_select(|app: &mut App, value| app.order = value),
            button("Review").key("review").on_click(|app: &mut App| app.review = true),
        ].gap(12., Axis::Vertical).padding(20., Edge::All),
        dialog(vstack![
            text(format!("Review: {}", app.draft)),
            button("Done").key("done").on_click(|app: &mut App| app.review = false),
        ].gap(12., Axis::Vertical))
            .key("review-dialog").title("Review draft").open(app.review)
            .on_dismiss(|app: &mut App| app.review = false),
    ].into()
}
view(&App::default()).build()?;

Text fields and areas support selection, clipboard, undo/redo (64 steps), IME composition and .password(true) masking. Enter calls on_submit in a single-line field; Cmd/Ctrl+Enter submits a text area. .soft_wrap(true) wraps long lines without changing the stored text. .read_only(true) allows a field without on_change. .leading_icon(Icon::Search) and .trailing_action(..) add adornments. Each editor holds up to 8 KiB of plain text: it is not a rich text or code editor.

Sliders take a finite range and step and respond to dragging and the arrow, Page and Home/End keys. range_slider(lo, hi) has two thumbs that cannot cross.

Select shows 1–128 typed options in a popup that flips above its trigger near the window edge and scrolls long lists. combobox adds type-to-filter.

Dialogs are modal inside the window: they trap Tab, restore focus on close, and dismiss with Escape or a backdrop click unless you disable either. Place the dialog after the content it covers in a root zstack!.

Menus and overlays

rustSource
use volt_ui_kit::ui::prelude::*;
#[derive(Default)]
struct App { menu_open: bool, inspector_open: bool, last_action: u8 }
fn view(app: &App) -> Element<App> {
    vstack![
        menu("Actions", [menu_item(1u8, "Save"), menu_separator(),
             menu_item(2, "Delete").danger(true), menu_item(3, "Later").enabled(false)])
            .key("actions").open(app.menu_open)
            .on_open_change(|app: &mut App, open| app.menu_open = open)
            .on_action(|app: &mut App, action| app.last_action = action),
        tooltip("Inspect this workspace",
            button("Inspector").key("inspect")
                .on_click(|app: &mut App| app.inspector_open = true))
            .key("inspect-help"),
        popover(text("A controlled, anchored card"))
            .key("inspector").anchor("inspect").open(app.inspector_open)
            .on_dismiss(|app: &mut App| app.inspector_open = false),
    ].gap(12., Axis::Vertical).into()
}
view(&App::default()).build()?;
  • Menus support separators, disabled and danger items, check and radio items, shortcut hints and menu_submenu (which opens in place with a back row). Arrow keys skip disabled items; Enter commits; Escape or an outside click closes.
  • Context menus: context_menu(target, items) opens on right-click at the pointer. Store the point from .on_context_open(|app, point| ..).
  • Tooltips appear immediately on hover or keyboard focus, need no state and never block input.
  • Popovers and hover_card anchor to another element by key.
  • drawer, accordion, collapsible, toaster and command_palette complete the set. Toasts are dismissed by your state; there is no timer.

These are drawn by the kit inside the window, not OS menus. For the macOS menu bar, see Application services.

Large lists

rustSource
use volt_ui_kit::ui::prelude::*;
struct App { window: std::ops::Range<usize>, selected: Option<usize> }
fn view(app: &App) -> Element<App> {
    virtual_list(10_000, 32., |index|
        data_item(index, format!("Record {index:05}")).key(format!("record-{index}")))
        .key("records").height(300.).window(app.window.clone()).overscan(2)
        .selected(app.selected)
        .on_window_change(|app: &mut App, window| app.window = window)
        .on_select(|app: &mut App, id| app.selected = Some(id))
        .into()
}
view(&App { window: 0..12, selected: None }).build()?;

Only the rows in the current window (at most 96) are built, so a model of any size stays within the element budget. Rows have a fixed height of 8–512 px. Scrolling reports a new window through on_window_change; store it and the next view builds those rows.

Tables, trees and split panes

rustSource
use volt_ui_kit::ui::prelude::*;
#[derive(Default)]
struct App { selected: Option<usize>, expanded: Vec<usize>, ratio: f32 }
let table = table([table_column(0usize, "Name"), table_column(1, "Status")], [
    table_row(1usize, ["Beta", "Ready"]).key("beta"),
    table_row(2, ["Alpha", "Review"]).key("alpha"),
]).key("projects").sort(0, SortDirection::Ascending).selected(None)
    .on_sort(|_: &mut App, _column, _direction| {})
    .on_select(|app: &mut App, id| app.selected = Some(id));
let tree = tree_view([
    tree_node(1usize, "Workspace").key("workspace").children([
        tree_node(2, "main.rs").key("source-main")]),
]).key("sources").expanded([1]).selected(None)
    .on_select(|app: &mut App, id| app.selected = Some(id))
    .on_expand(|app: &mut App, id, open| {
        app.expanded.retain(|value| *value != id);
        if open { app.expanded.push(id); }
    });
let ui: Element<App> = split(table, tree).key("workspace-split")
    .ratio(0.55).min_first(160.).min_second(120.)
    .on_resize(|app: &mut App, ratio| app.ratio = ratio).into();
ui.build()?;
  • Tables sort rows by the displayed text, or by .sort_by(..) for numbers and your own orderings. Columns can .align(Align::End) for amounts. A table with a fixed size scrolls in both directions. Tables are not virtualized.
  • Trees mount only expanded branches; selection and expansion are separate.
  • Split panes have a draggable divider (arrow keys work too). Use .ratio or pixel sizing, minimum sizes for each side, and .handle_style(..) for a divider that appears only on hover.

Charts

sparkline, bar_chart and line_chart draw small static charts. The larger charts (area_chart, candlestick_chart, donut_chart and stacked_bar_chart) become interactive when you give them a key:

rustSource
use volt_ui_kit::ui::prelude::*;
#[derive(Default)]
struct App { quarter: Option<usize> }
fn revenue(app: &App) -> Element<App> {
    stacked_bar_chart(
        ["Q1", "Q2", "Q3", "Q4"],
        [("Product", vec![120., 160., 190., 240.]), ("Services", vec![80., 90., 120., 130.])],
    )
    .key("revenue")
    .size(480., 240.)
    .selected(app.quarter)
    .on_select(|app: &mut App, i| {
        app.quarter = if app.quarter == Some(i) { None } else { Some(i) };
    })
    .into()
}
revenue(&App::default()).build()?;
  • With .key(..), every data point gets a value tooltip on hover or keyboard focus, and a spoken label for screen readers.
  • .selected(..) draws the highlight (a candle band and close line, an area rule with dots, a popped-out donut slice, an emphasised column); .on_select(..) reports clicks and Enter.
  • Donut clicks count only inside the ring; legend rows select slices.
  • Candle::new(open, high, low, close).volume(v) builds candlestick data; .value_format(f) formats tooltip and axis values.

Icons

rustSource
use volt_ui_kit::ui::prelude::*;
let logo = SvgIcon::parse(
    r##"<svg viewBox="0 0 24 24"><path d="M4 12h16M12 4v16" stroke="#000" stroke-width="2"/></svg>"##,
)?;
let row: Element<()> = hstack![
    icon(Icon::Search).size(16.),
    svg_icon(&logo).size(20.),
    svg_icon(&logo).size(20.).keep_colors(true),
]
.gap(8., Axis::Horizontal)
.into();
row.build()?;
  • 65 built-in vector icons on a 24-unit grid (icon(Icon::..)), tinted by the surrounding text colour.
  • Any SVG icon set works: SvgIcon::parse(markup) or SvgIcon::load(path), then svg_icon(&icon). SVG icons take the text colour unless .keep_colors(true) keeps their own colours.
  • IconSet::from_dir(path) loads a folder of .svg files by file name and reports the ones it could not read; set.icon("name") returns an element.
  • The SVG reader handles paths and basic shapes, transforms, fills and strokes. It never runs scripts or loads external resources.

Hierarchy charts

Icicle bands show parent/child depth; squarified treemaps show the root's direct children as proportional rectangles. Both use native Volt controls, not a webview.

rustSource
use volt_ui_kit::ui::prelude::*;
let nodes = vec![
    HierarchyNode::new("root", "Projects", 100, None),
    HierarchyNode::new("rust", "Rust", 60, Some(0)),
    HierarchyNode::new("build", "Build output", 40, Some(1)),
    HierarchyNode::new("source", "Source", 20, Some(1)),
    HierarchyNode::new("web", "Web", 40, Some(0)),
];
let explorer: Element<String> = icicle_chart(nodes.clone())
    .key("folders").size(640., 240.).levels(4)
    .on_select(|selected: &mut String, key| *selected = key)
    .into();
explorer.build()?;
let alternate: Element<String> = treemap_chart(nodes)
    .key("space").size(640., 240.)
    .on_select(|selected: &mut String, key| *selected = key)
    .into();
alternate.build()?;
  • Values are inclusive subtree totals; never add a parent total to its descendants. Direct children's sum must not exceed their parent's value.
  • One root first, parents before children, unique keys, at most 16,384 nodes and depth 64. Zero values do not create tiles. Invalid data rejects the tree.
  • .value_format(..) formats exact tooltip/accessibility values. Tab/Enter and pointer activation return the original node key. App-owned drilldown replaces the data with the selected subtree; keep a companion table.
  • .size(w, h) uses logical pixels. Use a containing stack's .on_width(..) callback for responsive sizes; layouts are not computed every animation frame.
  • Tiny tiles are not inflated into misleading sizes. Unrepresented child bytes leave blank area; provide an explicit Other node when grouping small items.
  • Strata-style interaction is opt-in: .selected_keys(..) supports multiple selections; .reviewed_keys(..) adds passive review diamonds, never checkboxes; .context_target(key) shows the menu target with a dashed outline. The legacy .selected(key) still replaces the selection with one key.
  • .node_colors(..) accepts bounded (key, color) overrides; unspecified nodes keep the original palette. Literal custom fills choose a contrasting black or white foreground. .hide_root(true) omits the icicle root band and makes .levels(n) count visible child bands; treemap geometry is unchanged.
  • .hover_linked(true) links tile hover to components with .hover_link(node_key) (for example, a file-list row). Links are paint-only: no callbacks, recomposition, selection, focus, scrolling or peer tooltips. Matching enabled, mounted peers use their own .hover_style(..); the nearest nested link wins. Keys are stable, nonempty strings up to 128 bytes. Hidden or unmounted counterparts do not scroll into view. Disable chart links and omit row links while an application-owned menu is open if its target should dominate.
  • .on_context_open(|app, key, point| ..) reports an action target without selecting it. point is window-logical pixels, not chart-local coordinates. Applications own the context menu, permissions, review and filesystem actions.
  • .keyboard_navigation(true) opts into roving focus: one Tab entry/exit, sibling Left/Right, parent Up, first visible child Down, sibling Home/End, Enter to activate. Native Shift-F10 / Context Menu opens the focused tile's actions. Disabled/removed targets and modal scopes retain their usual guards. Stable application node keys preserve focus identity when data reorders.
  • ui::icicle_layout / ui::treemap_layout expose pure geometry for testing or alternate native presentations. Treemap is one level per drilldown, not a claim to display every file at once.

Known limits

  • Range sliders expose one accessibility value; arrow keys move the last thumb you dragged.
  • Comboboxes and command palettes pick the best match on Enter; there is no Up/Down navigation through results yet.
  • Submenus open in place rather than cascading.
  • .offset(..) and slide/ambient motion move pixels only; layout and hit targets stay where they were.
