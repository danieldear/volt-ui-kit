Application lifecycle

State-aware commands and guarded closing for unsaved work.
Your state. Rust callbacks.

The previews below run the original Catalog declarations and Rust callbacks in WebAssembly. Native-only OS services are identified explicitly; this is not a simulation of desktop permissions or blur.

A guarded document

01 / 02

Edit the draft, use Save or Cmd/Ctrl+S, then request closing. Dirty work opens Save / Discard / Cancel. Saving here is in memory, not disk persistence.

How to use Rust source
Rust declarationSource
Application::new("Documents", app, view)
    .commands(commands())
    .requests(|app, sender| app.requests = Some(sender))
    .on_close_request(|app, reason| {
        if app.dirty() {
            app.close_prompt = Some(reason);
            CloseDecision::KeepOpen
        } else { CloseDecision::Close }
    })
    .run()?;
// Save / Discard: update app state, then enqueue Close(reason).
// Cancel: dismiss the dialog without closing or clearing the draft.

Catalog excerpt: names such as app, callbacks and helper functions belong to the example. View the complete source or start with the runnable app guide.

Window decorations and controls

02 / 02

Open Window settings in the header (at any width) to choose Native, Custom or Borderless and Symbols / Traffic lights. This preview only records actions; Custom embeds controls in the existing toolbar/sidebar, without adding a title strip, and honors the unsaved-work close guard.

How to use Rust source
Rust declarationSource
Application::new("Workspace", app, view)
    .app_id("com.example.workspace") // matches the Linux .desktop filename
    .on_window_diagnostics(|app, state| app.diagnostics = Some(state))
    .chrome_from_state(|app| app.chrome)
    .custom_resize_border(6.) // logical pixels, Custom mode only
    .window_actions(|app, sender| app.window_actions = Some(sender))
    .on_window_state(|app, state| app.window_state = state)
    .on_close_request(close_guard)
    .run()?;
// Linux/Windows: place controls inside your EXISTING draggable toolbar.
// macOS Custom retains native traffic lights; do not draw duplicate buttons.
window_header(text("Workspace"), window_controls_with_style(
    app.window_state.maximized,
    WindowControlStyle::TrafficLights, // or Symbols (legacy default)
    |app: &mut App, action| {
        if let Some(sender) = &app.window_actions { let _ = sender.send(action); }
    },
)).key("workspace-header");
// navigation_split_view(...).integrated_header(true).material(true)
// embeds controls without restyling the opaque, inset detail panel.
// .toolbar_translucent(true) separately opts into header glass (default false).
// The shell default and Application Native default remain unchanged.

Try it in the native Catalog

From the repository root. The browser previews cover shared components; run the native Catalog for OS integrations and native platform acceptance.

TerminalSource
cargo run --release --locked \
    --features native-gpu,native-desktop \
    --example catalog -- --page application-lifecycle

API reference

Properties and behavior documented by this Catalog page.

APIBehavior
CommandRegistry::new().command(...)Up to 256 validated, uniquely named Rust commands.
Command::enabled_when(predicate)Rechecked against current state before every execution.
Shortcut::primary('s')Exact Cmd/Ctrl logical letter/digit chord; optional shift/alt.
registry.entries(&app)Metadata for your own palette, buttons or other UI.
Application::on_close_request(callback)Close or KeepOpen; the developer owns dirty state and dialogs.
Application::chrome_from_state(f)Live Native / Custom / Borderless / macOS Overlay policy; no window replacement.
Application::window_actions(f) / on_window_state(f)Bounded typed control intents; native maximize/fullscreen/focus snapshots.
window_controls(maximized, on_action)Accessible vector controls; close goes through the host close guard.
window_header(content, controls)Shared existing-header composition; configurable height, gap and padding; no global title strip.
window_controls_with_style(state, style, f)Symbols or TrafficLights, with the same accessible intents and availability.
Application::app_id(id) / on_window_diagnostics(f)Linux identity plus actual backend, renderer, scale and blur request diagnostics.
Application::linux_backend(preference)Auto, Wayland or X11. Explicit unavailable backends fail, never silently fall back.
Application::requests(initialize)Bounded, event-driven commands and close requests; no idle polling.
